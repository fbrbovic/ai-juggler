## 1. Distribution & versioning

- **[V] Current version line: 2.1.x.** npm latest for `@anthropic-ai/claude-code` is **2.1.296** (checked 2026-10-12: https://registry.npmjs.org/@anthropic-ai/claude-code/latest); GitHub CHANGELOG HEAD is also 2.1.296 (https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md).
- **[V] Install methods (official overview):** native installer is primary — `curl -fsSL https://claude.ai/install.sh | bash` (macOS/Linux/WSL), PowerShell `irm https://claude.ai/install.ps1 | iex`; native installs "automatically update in the background". Also Homebrew (`brew install --cask claude-code`, stable channel, plus `claude-code@latest` channel; no auto-update), WinGet (`winget install Anthropic.ClaudeCode`), apt/dnf/apk. npm is no longer listed on the overview page (https://code.claude.com/docs/en/overview).
- **[V] Native binaries replaced the bundled JavaScript** in the week of April 13–17, 2026 ("native binaries replacing the bundled JavaScript", weekly release notes: https://code.claude.com/docs/en/whats-new/2026-w16.md).
- **[V] Desktop app exists** ("Claude Code Desktop"): macOS Intel/Apple Silicon, Windows x64/ARM64, Linux beta via apt; "A paid subscription is required"; features "parallel sessions with Git isolation, drag-and-drop pane layout, integrated terminal and file editor, side chats, computer use, Dispatch sessions from your phone" (https://code.claude.com/docs/en/overview and https://code.claude.com/docs/en/desktop.md). Release date **[U]**.
- **[V] IDE surface:** VS Code extension (inline diffs, @-mentions, plan review; also installs for Cursor) and JetBrains Marketplace plugin (requires CLI installed separately) (https://code.claude.com/docs/en/overview).
- **[V] Headless/API:** `-p`/`--print` non-interactive mode; `--output-format text|json|stream-json`; exit "code 0 on success and a non-zero code when the run fails", 143 on SIGTERM; stdin capped at 10 MB; `--bare` mode skips all auto-discovery and "requires `ANTHROPIC_API_KEY` since it never reads OAuth credentials" and "will become the default for `-p` in a future release" (https://code.claude.com/docs/en/headless).
- **[V] No `claude api` subcommand** exists in the current CLI reference (checked 2026-10-12). There is a bundled `/claude-api` slash-command skill that loads API reference material (https://github.com/anthropics/claude-code/issues/81312).
- **[V] GitHub repo** anthropics/claude-code: ~150.4k stars, no SPDX license detected via API (2026-10-12).

## 2. Configuration system

- **[V] Settings precedence (highest→lowest):** 1) Enterprise managed (`managed-settings.json`, MDM, or claude.ai console), 2) command line `claude --settings`, 3) project local `.claude/settings.local.json`, 4) shared project `.claude/settings.json`, 5) user `~/.claude/settings.json`. "When the same key appears in more than one place, Claude Code uses the value from the highest level that sets it" — list keys like `permissions.allow` merge (https://code.claude.com/docs/en/settings).
- **[V] Managed settings paths:** macOS `/Library/Application Support/ClaudeCode/managed-settings.json`; Linux/WSL `/etc/claude-code/managed-settings.json`; Windows `C:\Program Files\ClaudeCode\managed-settings.json`; optional `managed-settings.d/` and `managed-mcp.json`; MDM via macOS `com.anthropic.claudecode` profile domain, read at startup and "checked for changes every 30 minutes" (https://code.claude.com/docs/en/managed-settings).
- **[V] `--settings` flag:** inline JSON or file path (regular file ≤ 2 MiB); applies "above your user, project, and local files and below managed settings"; session-only, "doesn't write to any file" (https://code.claude.com/docs/en/cli-reference).
- **[V] `CLAUDE_CONFIG_DIR`:** "Claude Code then stores your settings, session history, and plugins there instead" — every `~/.claude` path relocates (https://code.claude.com/docs/en/claude-directory). **This is the isolation primitive for multi-account use.**
- **[V] `~/.claude` layout:** authorable — `CLAUDE.md`, `settings.json`, `keybindings.json`, `rules/`, `skills/`, `commands/`, `output-styles/`, `agents/`, `workflows/`, `themes/`; auto-generated — `projects/` (session transcripts, subagent transcripts, spilled tool results, file-history snapshots, auto-memory), `history.jsonl` ("Every prompt you've typed, with timestamp and project path"), `shell-snapshots/`, `stats-cache.json` (/usage totals), `remote-settings.json`, `policy-limits.json`, `plugins/`, `backups/`, `sessions/` (crash detection), `agent-memory/`, `daemon/`, `jobs/`; cleaned after `cleanupPeriodDays` (default 30) (https://code.claude.com/docs/en/claude-directory).
- **[V] `~/.claude.json` (separate file):** "holds your sign-in session" (OAuth), per-project trust decisions, personal MCP servers, global config; backed up before writes to `~/.claude/backups/` (https://code.claude.com/docs/en/settings).
- **[V] Key env vars** (https://code.claude.com/docs/en/env-vars): `ANTHROPIC_API_KEY` ("takes precedence over your subscription even if you are logged in"), `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN` ("OAuth access token as an alternative to `/login`; takes precedence over keychain credentials"), `ANTHROPIC_BASE_URL`, `ANTHROPIC_CUSTOM_HEADERS` (v2.1.227+), `ANTHROPIC_MODEL` / `ANTHROPIC_DEFAULT_MODEL`, `CLAUDE_CODE_MAX_OUTPUT_TOKENS`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, `CLAUDE_CODE_OAUTH_REFRESH_TOKEN` / `CLAUDE_CODE_OAUTH_SCOPES`; also the `apiKeyHelper` settings key (credential helper script, hot-reloaded).

## 3. Auth & multiple accounts

- **[V] Auth modes:** OAuth browser login for Pro/Max subscriptions; API key via `ANTHROPIC_API_KEY`; `claude setup-token` — "Generate a long-lived OAuth token for CI and scripts. Prints the token to the terminal without saving it. Requires a Claude subscription." (https://code.claude.com/docs/en/cli-reference).
- **[V] Credential storage:** macOS Keychain entry "Claude Code-credentials" (legacy/global); `.credentials.json` inside the config dir is the "login credentials" state file (https://code.claude.com/docs/en/claude-directory). **Per-config-dir keychain namespacing shipped in v2.1.56 (Feb 2026):** each `CLAUDE_CONFIG_DIR` gets its own entry `Claude Code-credentials-{sha256(configdir)[:8]}` with independent OAuth access+refresh tokens — confirmed by users in https://github.com/anthropics/claude-code/issues/20553. Before that fix, parallel OAuth profiles on macOS broke each other.
- **[V] No official multi-account support as of Oct 2026.** Open feature requests: `gh auth switch`-style switching — https://github.com/anthropics/claude-code/issues/30031; "First-class multi-account support: non-interactive account switching, path-independent credentials" — #89993 (2026-08-27); "See sessions across the Claude accounts I own on one machine" — #90188; profiles-within-one-account — #91770; desktop multi-account — #18435 (198 comments).
- **[V] Community pattern (dominant): per-account `CLAUDE_CONFIG_DIR` + aliases.** Canonical gist (219 stars): `alias claude-account1="CLAUDE_CONFIG_DIR=~/.claude-account1 claude"`; log in once per directory; run in separate terminals; "Each uses its own config and usage limits" (https://gist.github.com/KMJ-007/0979814968722051620461ab2aa01bf2). Same technique in writeups: Code Miner 42 (2026-03-19, https://blog.codeminer42.com/ai-tip-running-two-claude-code-accounts/), dev.to "Multi-Account Setup (Without Losing Context)" (Apr 2026), jguillaumesio.com (Jun 2026), fireup.pro (Aug 2026).
- **[V] Variant: direnv per-project auto-switching** — set `CLAUDE_CONFIG_DIR` per repo so work projects bill the work Max account (https://blog.ambi.se/two-claude-accounts-parallel, 2026-04-09; confirmed working in #20553 comments with namespaced keychain). Operator patterns overview (alias/direnv/symlink/SessionStart-hook): https://gist.github.com/yurukusa/d880ecc984af5d664f003daf85f956e3.
- **[V] GUI tooling:** **cc-switch** (https://github.com/farion1231/cc-switch, ~v4.x at ccswitch.io) — cross-platform desktop app switching Claude Code/Codex/Gemini CLI accounts; CLI helpers: `aisw`, `claude-code-accounts` (npm), `aimux`, `ccam`, `claude-code-account-switcher`. macOS-user separation and containers are discussed but with no definitive 2026 writeup **[U]**.
- **[V] Known gaps:** VS Code extension historically ignored `CLAUDE_CONFIG_DIR` — #30538 and #55621; third-party GUI Claudia reads credentials from `~/.claude` ignoring the var — #99921; billing attribution confusion — #87447; wrong tier shown after switching to a second Max 20x account — #94195.

## 4. Sessions

- **[V] Location:** `~/.claude/projects/<mangled-project-path>/<session-uuid>.jsonl` (project path with `/`→`-`); directory also holds subagent transcripts, spilled tool results, and file-history snapshots (https://code.claude.com/docs/en/claude-directory).
- **[V] JSONL shape (community-documented; format is internal/unofficial):** each line has `uuid`, `parentUuid` (conversation tree; `null` at roots), `sessionId`, `type` (user/assistant), `message` (role/content), `timestamp`, `cwd`, `version`, git branch; assistant messages carry a `usage` object with `input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens` (https://towardsai.net "Time Travel Debugging with Claude Code's Conversation", Jan 2026). Exact field set is **version-dependent [I]**.
- **[V] Resume flags:** `claude --continue`/`-c` loads most recent conversation in cwd; `claude --resume`/`-r` takes "a session ID, name, or transcript path" (absolute `.jsonl` path works) or shows a picker; `--session-id` forces a UUID; `--fork-session` creates a new ID when resuming. Since v2.1.285 resuming a running background session opens `claude attach` (https://code.claude.com/docs/en/cli-reference, https://code.claude.com/docs/en/headless).
- **[V] `/export`** command exists (bug reports #99452, #98290; feature request #93871) — export formats vary **[U]**.
- **[V] Checkpoints/rewind:** every prompt that starts a turn creates a checkpoint; file snapshots kept for the 100 most recent checkpoints, ~30-day retention; `/rewind` or double-Esc offers restore options; debug log `~/.claude/debug/<session-id>.txt` (https://code.claude.com/docs/en/checkpointing).
- **[V] Compaction:** `/compact` + auto-compaction; tunables `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`; `PreCompact`/`PostCompact` hooks (https://code.claude.com/docs/en/hooks).
- **[I] Third-party read-only access is trivially possible and tolerated in practice:** `ccusage` and others parse `~/.claude/projects` JSONL without complaints; statusline scripts receive `transcript_path`. No documented stability guarantee — pin to versions.

## 5. Usage & quota

- **[V] `/usage`:** plan usage bars, activity stats, breakdown; `d`/`w` toggles 24h vs 7 days; figures "come from local session history, so usage from other devices or claude.ai is not included"; backed by `stats-cache.json` (https://code.claude.com/docs/en/costs).
- **[V] Window mechanics:** rolling **five-hour session window plus weekly window**; windows "shared across all models, so the developer can't restore access by switching models with `/model`" (https://code.claude.com/docs/en/costs). Max plans: model-specific caps exist ("You've hit your Opus limit" is switchable; session/weekly limits are not).
- **[V] Weekly caps changed in 2026:** HN threads on cuts (2026-08-18, https://news.ycombinator.com/item?id=49350332) then a permanent 25% raise (2026-08-29, https://news.ycombinator.com/item?id=49492754).
- **[V] Exhaustion behavior:** "You've hit your session limit" / "You've hit your weekly limit"; on **v2.1.234+** Claude Code can "wait and continue the interrupted task automatically after the reset" (https://code.claude.com/docs/en/costs). Desktop auto-continues after reset since W33 2026 (https://code.claude.com/docs/en/whats-new/2026-w33.md).
- **[V] Programmatic detection:** (a) **statusline stdin JSON** includes `rate_limits.five_hour` and `rate_limits.seven_day` with `used_percentage` and `resets_at` — "present only for claude.ai Pro and Max subscribers" — plus `cost.total_cost_usd`, `context_window.*` (https://code.claude.com/docs/en/statusline); (b) **headless stream-json** emits `system/api_retry` events with error category `rate_limit` (v2.1.261+) and the final `result` message carries cost/session metadata (https://code.claude.com/docs/en/headless); (c) **hooks**: `StopFailure` ("When the turn ends due to an API error"), `Notification` on limit notifications (https://code.claude.com/docs/en/hooks).
- **[V] ccusage** (https://github.com/ccusage/ccusage, docs https://ccusage.com): reads local JSONL transcripts, extracts per-message token counts, aggregates daily/weekly/monthly/session/model, deduplicates repeated message IDs across resumed sessions, computes USD via per-model pricing tables. Related: CodeBurn (per-task token analysis, HN 2026-04-13, https://news.ycombinator.com/item?id=47759035).
- **[V] Telemetry pitfall:** usage is counted per full conversation resend at cached rates; thinking tokens billed as output; `/usage` reflects only the local machine (https://code.claude.com/docs/en/costs).

## 6. Extensibility surface

- **[V] Hooks** (https://code.claude.com/docs/en/hooks): `SessionStart`, `Setup`, `UserPromptSubmit`, `PreToolUse` (block/allow/deny/ask + `updatedInput`), `PermissionRequest`, `PermissionDenied`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `Notification`, `SubagentStart/Stop`, `Stop`, `StopFailure`, `PreCompact/PostCompact`, `Pre/PostModelSwitch`, `TaskCreated/Completed`, `ConfigChange`, `FileChanged`, `WorktreeCreate/Remove`, `SessionEnd`, and more. Handlers: `command`, `http`, `mcp_tool`, `prompt`, `agent`. Exit code 2 blocks; JSON `hookSpecificOutput` controls permission decisions.
- **[V] Plugins & marketplaces:** install scopes, official/community/demo marketplaces; components = skills+hooks+agents+MCP+commands (https://code.claude.com/docs/en/plugins/overview). Plugins are per-`CLAUDE_CONFIG_DIR`.
- **[V] MCP:** `.mcp.json` project servers, user MCP in `~/.claude.json`, `managed-mcp.json` for enterprises (https://code.claude.com/docs/en/mcp.md).
- **[V] Skills, subagents, commands, workflows:** `~/.claude/skills/`, `~/.claude/agents/`, `~/.claude/commands/`, `workflows/`; subagents run in background by default since W27 2026 (https://code.claude.com/docs/en/whats-new/2026-w27.md).
- **[V] Statusline:** `statusLine` setting runs a local script on session events (debounced 300 ms) with rich JSON (model, cost, context window, **rate limits**, transcript path); "runs locally and does not consume API tokens" (https://code.claude.com/docs/en/statusline).
- **[V] Headless/stream-json:** `-p` + `--output-format stream-json` emits `system/init` (with `capabilities`), messages, `stream_event` deltas, `hook_started/hook_response`, `system/api_retry`; final line is a `result` message (https://code.claude.com/docs/en/headless).
- **[V] Other surfaces:** OpenTelemetry metrics export (https://code.claude.com/docs/en/monitoring-usage), org analytics, Routines, channels, git worktrees for parallel sessions (`--worktree`, https://code.claude.com/docs/en/worktrees.md), `--teleport`/`--cloud` session mobility.

## 7. Terms of service

- **[V] Consumer Terms of Service** (https://www.anthropic.com/legal/consumer-terms): §2 — "You may not share your Account login information, Anthropic API key, or Account credentials with anyone else. You also may not make your Account available to anyone else." §3 — restricts accessing the Services via "automated or non-human means, whether through a bot, script, or otherwise," unless using an Anthropic API Key or where Anthropic explicitly permits; prohibits "bypass[ing] any of our systems or protective measures"; prohibits developing competing products or reselling the Services.
- **[V] No explicit "one account per person" or "multiple accounts" clause** found in the Consumer Terms (full-page fetch 2026-10-12). **[U]** whether one person owning 2+ paid subscriptions is prohibited — not addressed.
- **[V] Usage Policy** (https://www.anthropic.com/legal/aup): prohibits "Coordinate malicious activity across multiple accounts, or create multiple accounts, to avoid detection"; "Circumvent a ban through the use of a different account"; "Intentionally bypass or interfere with capabilities, restrictions, or guardrails"; "Resell, proxy, or otherwise provide access to Claude through unauthorized means."
- **[V] Commercial Terms** (https://www.anthropic.com/legal/commercial-terms): §A.1 permits using the Services "to power products and services"; §D.4 prohibits building competing products or reselling without approval.
- **[I] Reading for AI Juggler:** (a) one person running multiple paid Max accounts they own is not explicitly prohibited; the AUP's multi-account clause is conditioned on "to avoid detection"/malicious coordination — but "bypass … restrictions or guardrails" language means a tool advertising "rotate accounts to dodge limits" would be risky; (b) user-driven CLI automation is sanctioned in practice (`-p`, hooks, SDK, CI docs); (c) third-party wrappers are permitted to exist, but unauthorized resale/proxying of access is banned. **[U]** Enforcement stance on multi-Max-subscription individuals: no ban reports found; HN comment (~Sep 2026) openly describes running multiple Max 20x subscriptions (https://news.ycombinator.com/item?id=49492754).

## 8. Pain points (community evidence)

- **[V] Quota exhaustion mid-task:** "5-hour limit reached in less than 1h30" — 121 comments (https://github.com/anthropics/claude-code/issues/6457); GitHub search returns **724 issues** mentioning "5-hour limit" (2026-10-12). Hitting the 5-hour limit "kills in-flight workflow agents instead of pausing them" — #98299; usage spikes without activity — #94581, #91338, #100816; weekly-cap cuts — https://news.ycombinator.com/item?id=49350332; demand for a tier above Max 20x — #100980.
- **[V] Account juggling:** "Switching between personal and work Claude Code accounts is abysmal" — #22872 (18 comments); desktop multi-account — #18435 (198 comments); connector multi-account — #27302 (269 comments); VS Code ignoring `CLAUDE_CONFIG_DIR` — #30538; billing under the wrong account — #87447; wrong tier after switch — #94195.
- **[V] Session management:** conversation lost after resuming in a new terminal; JSONL corruption from concurrent writes crashes the CLI (Jan 2026 issues); `/export` gaps — #93871, #98290.
- **[V] Parallel/context:** auto-compact thrashing is a documented troubleshooting topic (https://code.claude.com/docs/en/troubleshooting.md); `/usage` is local-only, fragmenting quota visibility for multi-device users.

## Strategic takeaways for AI Juggler [I]

1. `CLAUDE_CONFIG_DIR` + per-dir namespaced keychain (v2.1.56+) is the stable, de facto multi-account mechanism — wrap it, don't fight it.
2. The statusline JSON (`rate_limits.five_hour/seven_day` with `resets_at`) is the cleanest programmatic quota feed for Pro/Max; parse `system/api_retry` `rate_limit` events + `StopFailure` hooks for exhaustion in headless runs; v2.1.234+ self-heals after reset.
3. Sessions are readable JSONL under each config dir — read-only parsing is proven at scale by ccusage; dedupe by message `uuid` across resumed files.
4. Version churn is fast (weekly minors with behavior changes) — pin and re-verify field shapes per version.
5. Stay on the right side of ToS: manage accounts a user owns, don't advertise limit-evasion, keep credentials per-account isolated.
