How to review this document

Each numbered screen below is a wireframe of a proposed change, drawn at desktop size with the real layout the implementation must follow: left rail, main column, and (where settled) the Right Inspector. Beside every wireframe you will find the controls list, the states that must exist, and the task IDs from docs/tasks/ that own the work. Your verdict per screen is stored in this browser only.

To approve: open this file, work top to bottom, and click Approve or Changes requested (with a note) under each screen. Then use Export approvals (JSON) in the top bar and hand the file back — agents will treat it as the approval record. Nothing here is built until the corresponding tasks move under the Stage-1 approval in the decision log.

Selected / primary Warning / estimated Blocked / destructive Verified / proven Beta / unvalidated

Vocabulary throughout: Provider (the tool), Account (a subscription/login), Instance (the tool running), Session (the conversation inside an Instance), Launch settings (formerly Profile). Decisions D-01…D-15 in docs/review/decision-log.md govern every screen; where a wireframe and a decision disagree, the decision wins and the wireframe must be fixed.

22Verify-before-kill sheet — the safety moment

Tasks: AJ-E507, AJ-E503 · Epic E5

Clean this leftover?

CheckResult
Spawned by Juggler for Codex·WorkLedger #4812 ✓
Same process (start time + command line)Match ✓
Parent Instance still running?No — closed 2h ago ✓
Unsent work / listening user service?Dev server — restartable, no state

Juggler will ask it to stop politely (TERM), wait 5s, then force (KILL) only if needed. This is recorded in the audit log. It will never clean a process it cannot verify.

If any check fails, this sheet becomes “Cannot verify — will not clean” with the reason. Fail-closed by design.

Purpose

One false kill destroys trust; this sheet is the evidence the user sees before trusting Clean.

Controls

  • Fail-closed: failed check disables Clean and says why
